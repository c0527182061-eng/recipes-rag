# 🍰 עוזר המתכונים – מערכת RAG על ספר המתכונים המשפחתי

מערכת שעונה על שאלות בשפה טבעית מתוך ספר מתכונים (קובץ Word), ומציגה את המתכונים שעליהם התשובה מבוססת.
המערכת עונה **רק** לפי ספר המתכונים, ואם אין בו תשובה היא אומרת זאת במפורש.

---

## 1. מבנה הפרויקט

```
recipes-rag/
├── data/
│   └── recipes.docx     ← ספר המתכונים (בסיס הידע)
├── ingest.py            ← שלב ההכנה: קריאה, חלוקה, Embeddings, שמירה
├── app.py               ← שלב השאלות: צ'אט Streamlit
├── requirements.txt     ← רשימת הספריות
├── .env                 ← מפתח ה-API (לא מגישים!)
├── chroma_db/           ← המאגר הווקטורי (נוצר אוטומטית ע"י ingest.py)
└── README.md
```

---

## 2. ארכיטקטורת המערכת

המערכת בנויה משני שלבים נפרדים:

### שלב הכנה (Offline) – `ingest.py`
רץ פעם אחת, ושוב רק אם ספר המתכונים משתנה.

```
recipes.docx
    ↓  read_recipes()      קריאת ה-Word וחלוקה לפי כותרות
102 מתכונים
    ↓  build_documents()   כל מתכון → Document + metadata
102 Documents  (metadata: source, category, recipe_title)
    ↓  SentenceSplitter    רשת ביטחון למתכון ארוך במיוחד
102 Nodes
    ↓  Gemini Embedding    כל מתכון → וקטור
    ↓  ChromaDB            שמירה בדיסק (chroma_db/)
```

### שלב שאלה (Online) – `app.py`

```
שאלת המשתמשת
    ↓  retrieve_recipes()   Embedding לשאלה + חיפוש 5 המתכונים הקרובים (cosine)
5 מתכונים
    ↓  generate_answer()    הנחיית מערכת + שאלה + מתכונים → Gemini
תשובה + "מקורות: 1,3"
    ↓  split_sources()      הפרדת שורת המקורות מהתשובה
תשובה + רק המתכונים שהמודל השתמש בהם
    ↓  Streamlit            הצגה + מקורות + זמני תגובה
```

## 3. בחירות טכנולוגיות

| רכיב | בחירה | למה |
|---|---|---|
| שפה | Python 3.12 | דרישת התרגיל; 3.12 נתמכת היטב ע"י כל הספריות |
| ספריית RAG | LlamaIndex | דרישת התרגיל; מספקת Documents, Node Parser, Index ו-Retriever מוכנים |
| מודל Embeddings | `gemini-embedding-001` | חינמי, ותומך ביותר מ-100 שפות, כולל עברית |
| מודל שפה (LLM) | `gemini-3.5-flash-lite` | חינמי ומהיר. ניתן להחלפה דרך `.env` |
| Vector Store | ChromaDB (מקומי) | מומלץ בחוברת לפרויקט לימודי; נשמר בדיסק בלי שרת |
| ממשק | Streamlit | צ'אט בדפדפן בכמה שורות קוד |

### החלטות עיצוב עיקריות

- **חלוקה לפי מבנה המסמך (Structure-aware chunking):** בקובץ ה-Word, כותרת 1 היא קטגוריה וכותרת 2 היא שם מתכון. כל מתכון נשמר כ-chunk אחד שלם, כדי שרשימת מצרכים לא תיחתך באמצע.
- **Metadata:** לכל מתכון נשמרים `category` (פרווה / חלבי / בישולים...) ו-`recipe_title`, כדי שאפשר יהיה להציג מקור ברור.
- **`temperature=0`:** המודל צמוד לטקסט ולא "יצירתי", כדי שכמויות יועתקו בדיוק.
- **הנחיית מערכת:** המודל עונה רק מהמתכונים שסופקו, מעתיק כמויות בדיוק, מציין את שם המתכון, ומחזיר "לא מצאתי" כשאין מידע.

## 4. התקנה (פעם אחת)

**דרישות:** Python 3.12 (בהתקנה לסמן ✅ Add python.exe to PATH).

בטרמינל (PowerShell), בתוך תיקיית הפרויקט:

```
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### מפתח API (חינמי)
1. נכנסים ל-aistudio.google.com ומתחברים עם חשבון Google
2. Get API key ← Create API key
3. יוצרים קובץ `.env` בתיקיית הפרויקט:

```
GEMINI_API_KEY=המפתח-שלכם
GEMINI_CHAT_MODEL=gemini-3.5-flash-lite
```

> ⚠️ את קובץ `.env` לא משתפים ולא מעלים ל-GitHub. המפתח הוא כמו סיסמה.

## 5. הרצה

בכל טרמינל חדש מפעילים קודם את הסביבה:
```
.\.venv\Scripts\Activate.ps1
```

```

```
פלט צפוי:

```
streamlit run app.py
```
הדפדפן ייפתח בכתובת `http://localhost:8501`. לעצירה: `Ctrl+C` בטרמינל.

## 7. בעיות שנתקלתי בהן ואיך שיפרתי

### בעיה 1: חלוקה לפי מספר מילים חותכת מתכונים באמצע
**הבעיה:** בקוד הבסיס החלוקה הייתה ל-250 מילים קבועות. בספר מתכונים זה גורם לכך שרשימת המצרכים של מתכון אחד נחתכת באמצע, ותחילת המתכון הבא נדבקת אליה. כתוצאה מזה המודל יכול לקבל כמויות של מתכון אחר.

**השיפור:** חלוקה לפי מבנה המסמך. הקוד מזהה את סגנונות הכותרות ב-Word (כותרת 1 = קטגוריה, כותרת 2 = מתכון), וכל מתכון נשמר כ-chunk אחד שלם, עם metadata של קטגוריה ושם. `SentenceSplitter` עם `chunk_size=1024` נשאר רק כרשת ביטחון.

**בדיקה:** הרצתי על ספר המתכונים את החלוקה המקורית (250 מילים, חפיפה של 40). נוצרו 26 קטעים, ו-**25 מתוך 26 ערבבו כמה מתכונים**. לדוגמה, הקטע שמכיל את "עוגת דבש" מתחיל באמצע מתכון "שמרים שוקולד עסיסי" ונגמר באמצע רשימת המצרכים של "רוגלך אלופים".

**התוצאה:** 102 מתכונים = 102 קטעים, אף קטע לא מערבב מתכונים, ולכל תשובה יש מקור ברור.

### בעיה 2: הצגת מקורות לא רלוונטיים, גם כשלא נמצאה תשובה
**הבעיה:** החיפוש ב-ChromaDB מחזיר תמיד את 5 המתכונים הקרובים ביותר, גם כשהם לא קשורים. הקוד הציג את כל 5 כמקורות. כך, על "איך מכינים סושי?" התשובה הייתה "לא מצאתי", ומתחתיה הופיעה רשימת מתכונים, בסתירה לתשובה.

**השיפור:** הוספתי להנחיית המערכת כלל: בסוף התשובה המודל כותב שורה `מקורות: 1,3`, או `מקורות: אין`. הפונקציה `split_sources()` מפרידה את השורה מהתשובה, ומוצגים רק המתכונים שהמודל השתמש בהם. נוספו רשתות ביטחון: אם המודל לא כתב שורה, אם הדגיש אותה, או אם כתב מספר שלא קיים.

**התוצאה:** על שאלה שאין לה תשובה לא מוצגים מקורות, ועל שאלה רגילה מוצג רק המתכון הרלוונטי.

### בעיה 3: זמן תגובה ארוך
**הבעיה:** עם המודל `gemini-3.8-flash` התשובות לקחו זמן רב, כי זה מודל עם שלב "חשיבה" לפני התשובה, ולשאלות על מתכונים אין בו צורך.

**השיפור:**
1. מעבר ל-`gemini-3.5-flash-lite`, מודל מהיר יותר. ההחלפה נעשתה דרך `.env`, בלי לשנות קוד.
2. הוספתי מדידת זמנים נפרדת לחיפוש ולתשובה (`time.perf_counter`), שמוצגת מתחת לכל תשובה, כדי לדעת איפה הזמן הולך במקום לנחש.

**התוצאה:** המהירות השתפרה מאוד. מהמדידה עולה שהחיפוש מהיר (פחות משנייה) ורוב הזמן הולך על יצירת התשובה.


### מגבלות ידועות
**1. שאלת המשך בלי שם המתכון.** כל שאלה מטופלת בנפרד: גם החיפוש וגם המודל מקבלים רק את השאלה הנוכחית, בלי היסטוריית השיחה. לכן אחרי "סילקא", השאלה "אין הוראות הכנה?" עלולה להחזיר "לא מצאתי", כי במילים האלה אין "סילקא". כשכותבים את שם המתכון בשאלה ("בסילקא אין הוראות הכנה?"), התשובה נכונה.

ניסיתי לפתור זאת: הוספתי לחיפוש את שמות המתכונים מהתשובה הקודמת. שאלות ההמשך הצליחו, אבל נוצרה בעיה חמורה יותר: כשהחלפתי נושא, המילים של הנושא הקודם "השתלטו" על החיפוש. אחרי רשימת עוגות, השאלה "מנות אחרונות" החזירה שוב עוגות ואז "לא מצאתי". **ביטלתי את השינוי**, כי עדיף שהחיפוש יהיה מדויק לכל שאלה בפני עצמה, גם במחיר של שאלות המשך. בהמשך הסרתי גם את שליחת ההיסטוריה למודל, כי בלי חיפוש שמשתמש בה התועלת שלה הייתה קטנה, והיא הוסיפה טוקנים וזמן.

**2. בקשת "כל ה..."** שאלה כמו "תביא את כל העוגות" מחזירה עד 5 עוגות בלבד, כי החיפוש שולף 5 מתכונים (`TOP_K=5`). הגדלת `TOP_K` או `chunk_size` הייתה פוגעת בשאר השאלות: יותר רעש, יותר טוקנים ותשובות פחות מדויקות. פתרון אפשרי להמשך: **Metadata Filtering**, כלומר הוספת שדה "סוג מנה" לכל מתכון וסינון לפיו בשאלות מסוג "כל ה...".
